# Bug 平台业务流程总览（Admin + H5）

## 1. 账号体系与角色边界

- 统一账号体系（同一 `user` 表），角色分为：
  - `USER`：普通用户（H5 主体使用者）
  - `ADMIN`：普通管理员（运营角色）
  - `SUPER_ADMIN`：超级管理员（治理角色）
- 端侧定位：
  - `H5`：面向普通用户的发布/承接/沟通流程
  - `Admin`：面向运营与治理，负责订单监管、用户管理、规则配置、日志审计
- 权限边界（当前实现）：
  - H5 写操作（发布、承接、状态更新）仅允许 `USER`
  - Admin 后台能力按角色分级；`SUPER_ADMIN` 拥有最高治理权限（如删除任意订单）

## 2. H5 业务流程（USER）

### 2.1 登录与会话

1. 用户登录（用户名/手机号/邮箱 + 密码）
2. 后端签发 JWT
3. 前端请求头携带 `Authorization: Bearer <token>`
4. 若接口返回 401，前端自动清理 token 并跳转登录（带 redirect 回跳）

### 2.2 发布需求

1. 进入“发布”页，填写标题、技术栈、问题描述、预期效果
2. 提交后创建订单，初始状态为 `PENDING`
3. 发布人可在“我发布的”查看自己的订单

### 2.3 承接需求

1. Bug 广场默认展示可承接订单（`PENDING`）
2. 用户进入详情页点击承接
3. 后端校验：
   - 订单必须是 `PENDING`
   - 发布人不能承接自己发布的订单
4. 承接成功后状态变更为 `TAKEN`

### 2.4 状态流转

1. 承接后进入沟通流程（可更新状态）
2. 用户在权限允许范围内执行状态更新（带可选备注）
3. 系统写入操作日志，便于追溯

### 2.5 删除规则（H5）

1. 发布人可删除自己的需求
2. 仅当“未被承接”时可删（`PENDING` 且无 `takerId`）
3. 已承接需求不可删除

## 3. Admin 业务流程（ADMIN / SUPER_ADMIN）

### 3.1 登录与准入

1. 管理员登录后台
2. 路由守卫校验管理员身份
3. 按角色渲染菜单与功能权限

### 3.2 订单运营（ADMIN + SUPER_ADMIN）

1. 查看订单列表与统计（按状态、关键词、时效筛选）
2. 查看订单详情（发布人、承接人、状态、时效、备注）
3. 运营介入：跟进状态与时效处理

### 3.3 治理能力（SUPER_ADMIN）

1. 删除任意订单（软删除，用于恶意内容治理）
2. 人工介入高权限操作
3. 用户角色与状态管理（分配角色、禁用、软删除）
4. 查看全量操作日志与时效规则高级配置

## 4. 时效与风控闭环

1. 定时任务按规则扫描订单时效
2. 订单标记为正常/预警/超期
3. 后台按时效状态集中处理
4. 关键操作全链路记录日志

## 5. 核心设计结论

- H5 聚焦“业务撮合”，Admin 聚焦“运营治理”
- 同一账号体系 + 强权限边界，可兼顾实现复杂度与治理能力
- `SUPER_ADMIN` 兜底治理能力（删单、介入、审计）是生产可运营关键
